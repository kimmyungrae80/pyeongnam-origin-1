# 주간 저장소 점검 체크리스트

**평남 오리진 프로젝트 - 관리자용 주간 운영 체크리스트**

---

## 📅 점검 일정

**매주 월요일 오전 10시**에 실행

- 약 5분 소요
- Google Calendar / Slack 알림 설정 권장
- 점검 결과를 기록

## ✅ 주간 체크리스트 (5분)

### 1️⃣ 저장 용량 확인
```
[ ] 관리자 콘솔 접속
    → https://your-domain.com/admin
    
[ ] 저장 용량 모니터 확인
    ├─ 사용률 확인 (목표: <70%)
    ├─ 승인된 제출물 수 확인
    └─ 평균 파일 크기 확인
    
[ ] 상태 판정
    ├─ 녹색 (Safe): 조치 없음
    ├─ 주황색 (Warning): 기록하고 감시 강화
    └─ 빨강색 (Critical): 즉시 알람 및 비상 회의
```

### 2️⃣ 새로운 제출물 현황
```
[ ] 심사 대기 제출물 수: ___건
    → admin 대시보드 "심사 대기" 섹션 확인

[ ] 지난주 신규 제출물: ___건
    → Supabase에서 최근 7일 제출물 count

[ ] 추세 분석
    ├─ 증가 추세인가? (참여도 up ✅)
    └─ 감소 추세인가? (참여도 down ⚠️)
```

### 3️⃣ 파일 타입 현황
```
[ ] 파일 타입별 통계 (Supabase에서 직접 확인)

SELECT content_type, COUNT(*) as count, AVG(array_length(file_urls, 1)) as avg_files
FROM submissions
WHERE status = 'approved'
GROUP BY content_type;

결과:
├─ 사진: __건 (평균 __개 파일)
├─ 영상: __건 (평균 __개 파일) ← 이것이 용량 차지의 핵심
├─ 에세이: __건
├─ 디자인: __건
└─ 기타: __건
```

### 4️⃣ 네트워크 사용 확인
```
[ ] 월간 다운로드 사용량 확인 (Supabase 한도: 2GB/월)
    → Supabase 대시보시 → Project → Bandwidth
    
[ ] 현황
    ├─ 안전: <1.5GB/월
    ├─ 주의: 1.5~1.8GB/월
    └─ 위험: >1.8GB/월
```

### 5️⃣ 비용 예측
```
[ ] 현재 추세로 계산한 월말 비용 예측

계산식:
(현재까지 사용량 / 경과일수) × 30일 = 월말 예상값

[ ] 10월말 최악의 경우 비용 예측
    = 현재 추세 × (경과 달수)
```

## 🚨 임계값 도달 시 조치

### 70% (700MB) 도달 시
```
🟠 경고 단계

즉시 조치:
[ ] 1. Slack / 이메일로 알림 송신
      → 내용: "저장소 사용률 70% 도달"
      
[ ] 2. 비상 회의 예약
      → Zoom / 대면 미팅
      → 의제: 유료 전환 시기 논의
      
[ ] 3. Vercel Blob 전환 준비
      → docs/storage-migration.md 검토
      → 필요한 권한 확인
      
[ ] 4. 비용 승인 프로세스 시작
      → 담당자에게 신청
      → 예산 배정 협의
```

### 85% (850MB) 도달 시
```
🔴 주의 단계

즉시 조치:
[ ] 1. 긴급 공지
      → 모든 관리자에게 알림
      
[ ] 2. Vercel Blob 설치 시작
      → `vercel integration add vercel-blob --yes`
      → 환경 변수 설정
      
[ ] 3. 테스트 환경에서 파일 업로드 테스트
      → vercel-blob 정상 작동 확인
      
[ ] 4. 배포 준비
      → 코드 검토
      → 롤백 계획 수립
```

### 95% (950MB) 도달 시
```
🔴 위험 단계 (즉시 조치 필요!)

긴급 조치:
[ ] 1. 프로덕션 배포
      → Vercel Blob 환경 전환
      → `vercel deploy --prod`
      
[ ] 2. 모니터링 강화
      → 배포 후 파일 업로드 테스트
      → 기존 파일 접근 가능 확인
      
[ ] 3. 신규 제출 수용
      → 이제 신규 파일은 Blob 저장
      → 기존 파일도 모두 접근 가능
```

## 💡 팁

### Supabase에서 직접 확인하는 방법
```bash
# 터미널에서 psql 접속 (필요시)
psql postgresql://...@db.supabase.co/postgres

# 제출물 통계 쿼리
SELECT 
  status,
  COUNT(*) as count,
  ROUND(AVG(array_length(file_urls, 1)), 2) as avg_files
FROM submissions
GROUP BY status;
```

### 로컬에서 빠른 확인
```bash
# Supabase 로컬 개발 환경 사용
supabase start

# 데이터 확인
supabase db query
```
